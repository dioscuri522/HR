## 0. エグゼクティブサマリー

- **「クロニキ」とは**、Threads でアカウント `@yoshiki.ai`（肩書き「Claude Code専門家」）を運用し、
  **AI（特に Claude Code）を使って複数SNSアカウントを自動運用し、短期間でフォロワーを急増させた**として
  話題になった日本の発信者。「**Claude Code に SNS 10アカウントを24時間回させ、月2万ドル超を稼ぐ**」という
  趣旨の動画／投稿で注目を集めた。
- 手法の本質は、新しい魔法ではなく **「既存のバズ型・収益化導線を、Claude Code というエージェントで
  “生成→投稿→分析→改善”まで自動化・並列化した」** 点にある。コンテンツ理論（フック、テンプレート、
  トレンド乗り）は従来から知られているもので、**差分は“人手の工数をAIに肩代わりさせて量とスピードを出した”** こと。
- 一方で、**数字（月2万ドル・10アカウント・「ポテト食ってるだけ」）の多くは検証困難で、同種の主張は
  複数の別アカウントでほぼ同一の動画・文言として拡散**しており、**情報商材／教材販売への導線**を伴う典型的な
  マーケティング構造を持つ。**規約違反（自動投稿によるBAN）・誇大表現・スキルのセキュリティ**といったリスクが大きい。
- 本レポートは、(1) 再現可能な実際の手法、(2) コンテンツ戦略、(3) マネタイズ構造、(4) 数字の信頼性とリスク、
  を切り分けて整理する。**「真似できる技術」と「真に受けてはいけない宣伝」を区別すること**が要点。

## 2. 何が起きたのか（急成長の全体像）

「AIで急速にフォロワーを伸ばした」現象は、次の3つの掛け算で説明できる。

1. **強烈なフック**: 「AIが勝手に稼ぐ」「人間は何もしない」という**欲求直撃の物語**。
2. **量とスピード**: Claude Code により **ネタ出し→投稿文生成→画像→投稿→分析→改善** を自動化し、
   1人で**複数アカウント・大量投稿**を回す。人手では不可能な試行回数を稼ぐ。
3. **収益化導線**: 伸びたフォロワーを **note/Brain等の教材販売・楽天/Amazonアフィリエイト・案件** に流す。

> 参考データ（同ジャンルで語られる“伸び”の例。**いずれも本人申告ベースで第三者検証はされていない**）:
> - あるAI運用スタートアップで「2か月で1万→15万フォロワー」。
> - 「知識実績ゼロのジャンル × Threads × 楽天アフィを2週間運用、Claude Codeで時短し1日1時間未満、
>    16万インプ／フォロワー約1000／月5〜10万円が見えてきた」(@toki_sns01 のThreads投稿)。
> - 楽天アフィ教材の宣伝文では「新規垢が1か月で5,000フォロワー」「30日で988万閲覧」「7投稿で初月5万円」等。

## 3. 手法の分解（再現可能な“技術”の部分）

ここがレポートの核。クロニキ／同ジャンルが実際にやっている（と公開情報から再構成できる）スタック。

### A. テクノロジー基盤 — Claude Code を「AI社員」化する

- **Claude Code をオーケストレーター**にして、SNS運用の各工程をスキル/ルーティン化する。
- ポイントは Claude Code の以下の機能を組み合わせること:
  - **Skills（スキル）**: 「一度やらせる → “スキル化して”と言う → 以後は特定キーワードで自動起動」。
    設定ファイルを1行も手書きせずに自動化レシピを量産（@sami_hoshino のThreadsで解説されている型）。
  - **Routines / Scheduled Tasks（定期実行）**: cron 的なスケジュールやワンショット実行、
    クラウド実行（PCを閉じても動く）に対応。「毎朝9時に投稿」「毎週月曜にまとめ」等を無人化。
  - **MCP コネクタ**: Typefully MCP（X下書き作成、OAuth/X API設定不要）、Pencil MCP × Meta Graph API
    （Instagram投稿）、Buffer/Hootsuite API（予約投稿）等を接続。
  - **Browser Use / ブラウザ操作**: API が開いていない操作をブラウザ自動操作で代替するパターンも。

### B. コンテンツ生成エンジン

典型的な“半自動パイプライン”:

1. **ネタ源**: Googleスプレッドシート等にネタリストを用意（or トレンド/バズ垢から自動収集）。
2. **生成**: Claude(API) で **X・Instagram・Threads・note・YouTube 用の投稿文を一気に並列生成**
   （「テーマを入れるだけで5媒体ぶん生成」型のマーケエージェント構成）。
3. **レビュー**: 生成物を別シートに出力して人間が（または別エージェントが）チェック。
4. **投稿**: 承認済みを Buffer/Typefully/各API で**予約投稿**。

### C. バズ設計（コンテンツの“型”）— ここは従来理論の流用

AIで量産しても、**当たる“型”に沿っていないと伸びない**。共通して使われる定石:

- **1行目のフック必須**: スクロールを止める。
  - 「あなたが知らない〇〇の真実」「常識と正反対の〇〇」「たった10秒でできる〇〇」など。
- **黄金比（よく引用される配分）**: **本文70% : ビジュアル20% : ハッシュタグ10%** に労力配分。
  （「10万件のバズツイート分析から」とされるが**出典は宣伝記事ベース**）。
- **投稿構成テンプレ**: `フック1行 → 箇条書き3〜5個 → CTA（保存・シェアを促す）`、
  専門用語を避け、絵文字を適度に、ハッシュタグは2〜3個。
- **トレンド乗り**: X API のトレンドエンドポイント等から旬ワードを拾い、それに沿って生成→拡散しやすくする。

### D. 複数アカウント並列運用 & 競合リサーチ

- **「数百個のバズ垢を常時リサーチ」**: 伸びている投稿の構造・テーマ・頻度を収集し、
  自分の生成プロンプトに反映する“模倣＋改変”ループ。
- **10アカウントを同時運用**: AIが各アカウントのトンマナで生成・投稿するため、
  1人で大量のアカウント＝大量の試行回数を確保（“下手な鉄砲も数撃ちゃ”戦略の自動化）。

### E. スケジューリング / 自動投稿

- ローカル cron / mac launchd / Claude Code Routines / クラウド実行 で**定時・定期投稿**を無人化。
- 「投稿ゼロ運用（人は投稿ボタンすら押さない）」を標榜する記事・教材が多数。

### F. 分析・改善ループ

- X API analytics 等で **インプレッション・エンゲージ率・フォロワー増減** を取得し、
  Claude にレポート化・次の打ち手提案までさせる **PDCAの自動化**。

## 4. マネタイズ構造（“フォロワーを何に換えているか”）

伸ばしたフォロワーは、概ね次の導線で収益化される（このジャンル共通）:

1. **アフィリエイト**: 特に **Threads × 楽天アフィリエイト**（顔出し不要・フォロワー少でも可を売りにする）、Amazon。
2. **教材・情報商材販売**: note / Brain で「自動化の全手順」「プロンプト配布」「セットアップファイル付き」を販売。
   （例: 「一人でも会社が回る Claude Code × AI社員16名」系の有料note 等）。
3. **コンサル・案件・コミュニティ**: 「自動化を組んであげる」「サロン」等。
4. **アカウント自体の販売／横展開**。

> **構造的注意**: 「AIで稼いだ」の主要な収益源が、しばしば**“AIで稼ぐ方法”を売ること**になっている
> （メタな自己言及構造）。フォロワー急増の実演そのものが、教材の最大の広告になっている。

## 5. 再現ブループリント（学習目的の最小構成）

クロニキ的スタックを**安全な範囲で**試すなら、最小構成は次の通り。

```
[ネタ源] Googleスプレッドシート / トレンドAPI
      │
      ▼
[生成]  Claude Code + Claude API
        - スキル化した「投稿生成」レシピ（媒体別トンマナをプロンプトに固定）
        - フック型・テンプレ（4章C）を system/skill に埋め込む
      │
      ▼
[レビュー] 人間が最終確認（←ここを自動化しないことがBAN回避と品質の肝）
      │
      ▼
[投稿]  Typefully(X) / Buffer / 手動投稿
      │
      ▼
[分析]  各API analytics → Claude にレポート＆改善案を出させる
      │
      └────（改善をプロンプト/テンプレに反映してループ）
```

- まずは **1アカウント・媒体1〜2個**で「生成＋分析」だけ自動化し、**投稿は手動**にするのが現実的かつ低リスク。
- 「スキル化して」の一言で再利用可能なレシピに育てる、という Claude Code の使い方が中核ノウハウ。

## 6. 数字の信頼性とリスク（最重要・批判的検証）

「徹底調査」として、**鵜呑みにすべきでない点**を明確化する。

### 6.1 主張の検証可能性
- **月2万ドル／10アカウント／「ポテト食ってるだけ」等の数字は、本人申告のみで第三者検証なし**。
- **同一の動画・ほぼ同一の文言が複数の別アカウント（クロニキ／なおき 等）で拡散**しており、
  「個人の実績」というより**ジャンル化したマーケティング・テンプレート**として流通している疑いが強い。
- 同ジャンルの正直な発信者は「**正直まだ大きな成果は出ていない。フォロワーは少ないしバズもない**」と
  認めている例もある（自動化の“仕組み”は作れても“成果”は別問題）。

### 6.2 プラットフォーム規約 / BANリスク
- **自動投稿はBotとみなされ、アカBAN（凍結）リスクが高い**。実務者も「投稿だけは手動が安全では」と懸念を表明。
- Instagram/X いずれも自動化・大量運用・複数アカウントはポリシー抵触の可能性。**“10垢24時間自動投稿”は特にハイリスク**。

### 6.3 サプライチェーン／スキルのセキュリティ
- 「Claude Code Skills」をうたう**SNS系・仮想通貨系スキルが、調査の結果すべて公開レジストリに実在しなかった**事例が報告されている。
  AIスキル全体の **36.8% に何らかの脆弱性**との指摘も。
- → **配布プロンプト／スキル／セットアップファイルを無検証で実行しない**。Anthropic公式リポジトリや
  キュレーション済みリスト（awesome-claude-skills 等）から取得する。

### 6.4 倫理・コンテンツの真正性
- AIインフルエンサー領域では、**他人の画像・動画を素材に盗用する「AIピンピング(AI Pimping)」**等の問題が報告。
- AI生成であることの非開示、フェイク実績、誇大広告は**景表法・各プラットフォーム規約**上の問題になり得る。

### 6.5 “レッドオーシャン化”
- 2026年春時点で **Threadsは「どこかで見た投稿」で飽和**。同じ自動化テンプレが大量流入し、
  **後発の伸びは鈍化**。「仕組みを買えば誰でも」は成立しにくくなっている。

## 7. 結論 — 何が本当に学べるか（チェックリスト）

**真似する価値がある（技術）:**
- [ ] Claude Code を「生成→分析→改善」のオーケストレーターにする発想。
- [ ] 「一度やらせて “スキル化して”」で再利用レシピを量産する運用。
- [ ] フック1行＋箇条書き＋CTA の投稿テンプレと、トレンド連動。
- [ ] 分析（インプ/エンゲージ/フォロワー増減）をAIにレポート化させ、改善をテンプレへ還流。

**距離を置くべき（宣伝・リスク）:**
- [ ] 「AIが勝手に月◯◯万」という**数字の鵜呑み**（検証不能・使い回しが多い）。
- [ ] **完全無人の自動投稿・多数アカウント運用**（BAN・規約違反リスク）。
- [ ] **出所不明の配布スキル/プロンプトの無検証実行**（セキュリティ）。
- [ ] 主目的が「稼ぐ方法を売る」化している構造への盲従。

> 要約: **クロニキの“手法”は新発明ではなく、「既知のバズ理論＋収益化導線」を Claude Code で
> 自動化・並列化・高速化したもの**。学ぶべきは**自動化アーキテクチャと運用の型**であり、
> **数字と再現性の主張は強い懐疑をもって検証**するのが正しい向き合い方。
